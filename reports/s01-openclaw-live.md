## 1. Come OpenClaw usa Claude Code (CODE, poi verificato)

- **Backend CLI `claude-cli`** del plugin `anthropic` (`dist/extensions/anthropic/cli-backend.js` -> `cli-backend-CL_vqU90.mjs`): argv `-p --output-format stream-json --include-partial-messages --verbose --setting-sources user --allowedTools mcp__openclaw__* --disallowedTools ScheduleWakeup,CronCreate,Bash(run_in_background:true),Monitor`, in piu' `--strict-mcp-config --mcp-config <tmp>/mcp.json`, `--plugin-*`, `--append-system-prompt-file`, `--model`, e **`--permission-mode bypassPermissions` quando la policy exec e' quella di default (`security=full ask=off`)** (CODE `cli-shared.js`, `normalizeClaudeBackendConfig`). Sottoprocesso **caldo** per sessione (`liveSession: claude-stdio`), che resta in vita tra un turno e l'altro (3 processi `claude` da 240-270 MB ciascuno osservati con 3 sessioni; TESTED).
- **Nessun override di comando**: `resolveCliBackendConfig` usa `backend.config.command` ("claude") e basta; la doc (`gateway/cli-backends.md`, `plugins/cli-backend-plugins.md`) dice di mettere nel `PATH` del servizio il comando registrato o di "cambiare/avvolgere la registrazione del plugin". Un wrapper dovrebbe quindi chiamarsi `claude` e stare davanti nel `PATH` (contrario alla lezione 2 dei test precedenti: qui non c'e' alternativa).
- **`exec` e' del Gateway**: `hostOwnedTools: ["exec","process"]` e `--disallowedTools Bash` per il processo Claude; la shell dell'agente e' `mcp__openclaw__exec` (bridge MCP loopback del Gateway). Osservato nella run: `toolSummary` = Glob, Read, Edit, `mcp__openclaw__exec` (9 chiamate, 0 fallimenti; TESTED). Quindi **un wrapper bwrap solo su `claude` lascerebbe `npm test` e ogni comando dell'agente eseguiti dal Gateway senza sandbox**. Per questo ho confinato il Gateway intero.
- **Autenticazione (CODE + DOC)**: `autoSelectAuthProfile: false`; la doc (`providers/anthropic.md`) dice che OpenClaw usa un "marcatore di rotta non segreto" e **non legge, salva, rinnova ne' inoltra i token del login nativo**; `claude auth status --json` e' la sonda di disponibilita' (via `PATH`). Esiste una `readClaudeCliCredentialsCached` (deprecated, per SDK plugin) che legge `~/.claude/.credentials.json`: non la ho vista usata nel percorso del backend, ma non ho tracciato tutti i chiamanti. **Controllo dopo le run (TESTED)**: nessun file di stato/log di OpenClaw contiene `sk-ant-` ne' `accessToken` (`openclaw-leakcheck.sh`). Il login resta quindi in mano a Claude Code; OpenClaw puo' invece inoltrare via fd profili salvati (`paste-token`, API key con selezione esplicita): non usati.
- **`--setting-sources user` e' fisso**: il `.claude/settings.json` del repository di fixture (che fissa il modello negli altri test) e' **ignorato**; il modello arriva da `--model` scelto da OpenClaw (config `agents.defaults.model`).
