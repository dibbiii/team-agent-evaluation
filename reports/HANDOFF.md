## Avvertenze per chi riprende

- Il `CLAUDE.md` globale dell'utente contamina le run `claude -p` se non si imposta `CLAUDE_CODE_DISABLE_CLAUDE_MDS=1`: verificarlo con una sonda prima di ogni lotto e leggere i riassunti degli agenti, non solo i test.
- Sul daemon Docker ci sono container e volumi dell'utente: toccare solo risorse `tae-` con label `tae=1`, mai `prune`.
- Il controllo automatico dei permessi di Claude Code ha bloccato (giustamente) una prova che avrebbe lanciato Claude Code **senza sandbox con i permessi disattivati** e con credenziali copiate, e il ping di rinnovo credenziali fuori da `bwrap` durante la prova del forge reale: non ritentare né aggirare.
- **Quoting:** wsl.exe + PowerShell rompono i comandi annidati (è già costato la cartella `C:\wsl.localhost\`). Usare script `.sh` copiati dentro la distribuzione dal lato Windows (`\\wsl.localhost\<distribuzione>\...`, fine riga LF).
- **DNS di WSL** non funzionante su questo PC (anche nella `Ubuntu` personale). Nella distribuzione dedicata (ora cancellata) `/etc/resolv.conf` era un file vero con 1.1.1.1 e 8.8.8.8 e `systemd-resolved` disattivato; se la si ricrea, non ripristinare il collegamento verso `/run`: la sandbox di Warren non monta `/run` e il DNS dentro la sandbox smette di funzionare (è costata una run).
- **Memoria:** la RAM disponibile dell'host oscilla (browser e WebView occupano diversi GB). Prima di una serie di run controllare la memoria *disponibile* (cache inclusa), non solo quella «libera»; la serie `warren-live-batch.ps1` si ferma sotto 1,5 GB.
- **Warren:** non esclude `.claude/` dai commit; con l'agente vero copia le credenziali nel workspace; cancellare il repository bare di prova dopo ogni run (`scripts/live/cleanup-run.sh`). Impostare `WARREN_GIT_AUTHOR_NAME`/`_EMAIL` per un'identità di macchina (senza, l'agente firma con nome ed email dell'utente: F30). Su forge reale il prompt completo finisce nel corpo della PR.
- **Candidati in LIVE (trappole da non ripetere):** Paperclip: impostare `engine: "cli"` (il motore ACP predefinito ignora il wrapper e ha già lanciato Claude Code fuori dalla sandbox) e lanciare il server con `setsid nohup`; Gas Town: preimpostare `~/.claude.json` (onboarding, tema, fiducia per percorso esatto di ogni worktree del polecat) e i pattern dei file di Gas Town in `.repo.git/info/exclude`, altrimenti `gt done` si blocca; OpenClaw: confinare l'intero Gateway, disattivare l'heartbeat (`agents.defaults.heartbeat.every = "0m"`); Paseo: password sempre impostata e wrapper con `env -i`; Warren: nessun `claude` sull'host fuori da `bwrap` (non lanciare `model-pin-check.sh`).
